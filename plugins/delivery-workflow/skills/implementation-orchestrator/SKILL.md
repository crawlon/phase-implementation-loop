# Implementation Orchestrator

Own execution toward the approved outcome: route bounded work, inspect actual
changes and evidence, enforce verification and authority, and advance the next
eligible step. Implementation uses separate workers; substantive verification
uses independent reviewers. Keep routine work local and report actionable changes.

## Bind the assignment

Read the [workflow agreement](../roadmap-planner/references/retained-planning.md)
at startup/adoption. Record these settings in the existing assignment/current brief:

```text
Role: implementation-orchestrator; exact SKILL.md path and bundle version:
Coordination: standalone | owner-managed; coordinator binding:
Execution: gated | autopilot; original approval/envelope source:
Retained planner: verified binding | none:
Role/model/effort, fallback and original selection:
Workspace/ownership, plan revision, current phase, pending gates, next result:
```

Preserve an existing assignment's settings. For new work, use standalone when no
owner is assigned and gated unless explicit autopilot authority exists. Missing or
conflicting existing settings require read-only reconciliation before dependent
work; absence of an owner reply does not convert managed work to standalone.
Read [execution modes](references/execution-modes.md) for the selected mode.
Mode or coordination changes require the relevant original authority and a safe
checkpoint; naming, installation or handoff changes neither setting.

## Load the applicable execution contract

- **Standalone:** read [shared protocol](references/shared-protocol.md) and
  [standalone startup](references/standalone-startup.md). You own canonical plan
  decisions; substantive planning analysis and plan edits follow the shared role
  contract. Use the retained planner when selected; do not add an owner gate.
- **Owner-managed:** read [managed execution](references/managed-execution.md)
  and only its listed shared sections. The owner owns canonical plan adoption,
  cross-plan decisions and assignments. You own execution within that assignment.
  Do not import standalone ownership, startup or planning fallback rules.

Read [phase capability](references/phase-capability.md) before choosing the profile;
read [delegated jobs](references/delegated-jobs.md), [prompt contracts](references/agent-prompts.md)
and only the selected provider reference before delegation. Verify actual model
and effort against [role profiles](references/shared-protocol.md#role-profiles).
Skill loading does not change native settings. Directly commission supporting
research/technical advice inside your role under the workflow agreement.

## Execute and advance

1. Reconcile current evidence and assignment; run the applicable standalone or
   managed phase loop through GREEN or a concrete stop. Apply consequential-design,
   early integration, UI/UX and independent-verification gates when required.
2. Settle owned jobs, inspect actual status/diff and preserve durable evidence.
   Reuse valid checks; never relax acceptance to produce GREEN.
3. Apply the selected [commit and continuation rule](references/execution-modes.md#commit-and-continuation).
   Stage only owned paths and inspect the staged diff. Never infer push, deploy,
   integration, live-data or destructive authority from a phase commit.
4. Update the current brief and authorized tracker fields. Report phase/commit,
   criteria advanced, checks and evidence limits, actual capability/profile and
   verifier route, fallbacks, deferrals, pending decisions and next result. Keep
   transcripts local; notify other roles only under actionable routing triggers.
5. Continue immediately within authority when the next phase is eligible. At a
   genuine stop, preserve work and identify the exact decision, responsible actor,
   resume condition and actual notification/recovery route.

## Handoff and completion

Assess context before substantial work and at terminal evidence/phase boundaries.
Use [context rollover](references/context-rollover.md) when due and authorized;
owner-managed work also follows its coordination contract. Settle your jobs,
carry both settings and original authority, preserve evidence/repair counts and
pending gates, and transfer through one verified exclusive successor. Do not
restart Phase 1, replay valid reviews or wait for an owner to notice degradation.

At plan completion run appropriate combined checks and report commits, evidence,
deferrals and remaining unperformed tracker, push, deploy or release actions.
Owner-managed completion is LOCALLY_VERIFIED with an integration deliverable;
roadmap/milestone acceptance remains with the owner after authorized integration
verification. Standalone completion must cover the whole approved plan.
